# コンテンツ作成ガイドライン
## ギター解説インフルエンサー分析 × X / Instagram / Threads 投稿方針

## PART 1｜語り手の人物解析

### 人となり・キャラクター

**「怖くない先生」タイプ**

専門知識は持ちながらも、威圧感を一切出さない。むしろ自分の無知・経験不足を積極的に開示する。

> 「僕もこんなことあんまやったことないんですけども」
> 「これ今適当に言ってますけどね」

この自己開示が「この人は正直だ」という信頼を生む。

**視聴者の感情を先読みして潰す**

視聴者が「でも…」と思う前に、自分からその疑念を口にして安心させる。

> 「なんかページによって書いてることちょっと違ったり、そもそもなんでその順なんだろうっていう」

「私だけじゃなかった」という安堵感を先に与える設計。

**「自由でいい」を繰り返す解放者**

ルールを教えながら、「でも縛られなくていい」と常に言い続ける。これが「権威に従わせようとしている感」を消し、視聴者を楽にさせる。

> 「絶対こうでないといけないっていうルールはありません」
> 「自分でねどっちの方が自分的には好きかなって」

---

### 話し方・トンマナ分析

| 要素 | 内容 | 例 |
|------|------|-----|
| **構造** | 結論先出し → 理由説明 → 実演検証 | 「じゃあ初めに早速答えですね」と先に全体図を見せる |
| **文体** | ですます調ベースの口語体 | 「〜ですよね」「〜じゃないですか」 |
| **擬音・体感語** | 感覚を言語化 | 「ギュって止めると」「ピュって消せる」 |
| **フィラー** | 自然な間をつくる | 「まあ」「ちょっと」「なんか」「やっぱ」 |
| **視聴者への語りかけ** | 常に「あなた」に話しかける | 「皆さんどうでしたか」「もう分かりますよね」 |
| **コメント誘導** | 双方向コミュニティ化 | 「コメント書いていただければ」「逆にこういう考え方もありますよって方は」 |
| **謙虚な限定表現** | 断言しない | 「基本的には」「〜かなと思います」「〜の方がいいかな」 |

---

### なぜバズるのか｜構造的分析

**① 「あるある」悩みへの共感ファースト**
冒頭で視聴者の「困った経験」をそのまま言語化する。「これは私のことだ」と思わせることで最後まで離脱させない。

**② 答えを先に出してから深める**
結論を最初に見せることで「なぜそうなのか知りたい」という知的好奇心を引き出す。

**③ 「完全版」というワード設計**
「完全版」は検索にも強く、「これを見れば全部わかる」という期待値を生む。

**④ ルールを教えながら「縛らない」安心感**
「これが正解だ」と押しつけず「でも自由でいい」と言い続けることで、初心者も上級者も受け入れられる間口の広さが生まれる。

**⑤ 実演・検証で信頼性を担保**
「言ってるだけ」ではなく実際の音で証明する。信頼 = 購買・シェアにつながる。

**⑥ コミュニティ感の醸成**
コメントを積極的に求め、「違う意見も歓迎」と言うことで視聴者が「参加者」になる。

## PART 2｜X・Instagram・Threads コンテンツ作成ガイドライン

---

### 基本原則（全媒体共通）

#### 原則1｜「あるある」から入る
最初の一文で視聴者の「困った・悩んだ・疑問に思った」体験をそのまま言葉にする。

```
❌ NG: エフェクターの接続順について解説します。
✅ OK: エフェクターの接続順、調べるたびにサイトによって言ってること違うんですよね。
```

#### 原則2｜結論を先に出す
「続きは動画で」型ではなく、価値を先に渡す。SNSでの信頼は「無料で価値を先出しする人」に集まる。

```
❌ NG: 正しい接続順が気になる方はぜひ動画をチェック！
✅ OK: 基本は「歪み前」→「歪み」→「歪み後」の3エリアで考えると全部解決します。
```

#### 原則3｜「でも自由でいい」を必ず添える
結論を言った後に必ず「縛られなくていい」という一言を加える。これがこのスタイルの最大の差別化要素。

```
ただこれは基本の話で、自分の好きな音がするならどんな順でもオッケーです。
```

#### 原則4｜断言しない・押しつけない
「〜だと思います」「基本的には〜」「〜かなと」という表現で、意見を柔らかく包む。

#### 原則5｜コメント・リプライを設計する
最後に「あなたはどうですか？」「他にこういう方法知ってる方いたら教えてください」で締める。

## X（旧Twitter）

**文字数目安:** 140〜280字（1ツイート完結型）or スレッド型

### 投稿フォーマット

```
1行目（Hook）  : 「あるある」悩みか、意外な事実
2〜4行目       : 結論 or ポイントを箇条書き
最終行         : 「自由でいい」付け足し or 問いかけ
```

### 例文テンプレート

```
エフェクター接続順、ネットで調べるたびに違うこと書いてあって混乱するやつ。

シンプルにこう覚えとけば大体解決します

・歪み前：ピッチ・コンプ・フィルター系
・歪みエリア：歪みペダル・ブースター
・歪み後：モジュレーション・空間系

ただこれあくまで基本なんで、自分の好きな音がするならどんな順でも全然アリです
```

### スレッド型（解説投稿）の構造

```
ツイート1: 「あるある」悩み提示 + 「今日全部解決します」
ツイート2: 結論（大枠）
ツイート3〜5: 各ポイントの詳細
最後のツイート: 「自由でいい」締め + コメント誘導
```

### X特有の注意点

- 改行を積極的に使い「読みやすい余白」を作る
- 箇条書きは3点まで（多すぎると読み飛ばされる）
- 「〜ですよね」「〜じゃないですか」で共感を引き出す

## Instagram

**キャプション文字数目安:** 300〜500字（最初の2行が命）

### 投稿フォーマット

```
1〜2行目（冒頭）: 「あるある」 or インパクトある問い（ここだけ表示される）
---（改行）---
本文: 結論 + 理由 + 実体験
---（改行）---
締め: 「でも自由でいい」+ コメント誘導
ハッシュタグ（5〜10個）
```

### 例文テンプレート

```
エフェクターの接続順、調べても毎回混乱してませんか？

今日でもう迷わなくなります。

シンプルに3つのエリアで考えるだけ。

▶ 歪み前エリア
ピッチ系・コンプ・フィルター・EQ
「ギターがそもそもこういう音だったら」って置き換えのゾーン

▶ 歪みエリア
歪みペダル・ブースター
ここで音のキャラを作る

▶ 歪み後エリア
モジュレーション・空間系
作った音をどう響かせるか

---

ただこれはあくまで基本の話。
自分の好きな音がする順番があればそっちで全然オッケーです。

みなさんはどんな順番で繋いでますか？コメントで教えてください！

#ギター #エフェクター #ギタリスト #エレキギター #ギター初心者
```

### Instagram特有の注意点

- 冒頭2行で「続きを読む」を押させる設計にする
- 絵文字は使いすぎず、アクセント程度（▶ ・ など）
- カルーセル投稿なら1枚目が「あるある」、最終枚が「まとめ＋自由でいい」
- ストーリーズでは「質問スタンプ」を使ってコミュニティ感を作る

## Threads

**文字数目安:** 150〜400字（Xより少しだけ長く書ける、会話感重視）

### 投稿フォーマット

```
独り言・気づき感覚で書く
→ 「〜って思いませんか？」「〜なんですよね」
→ 日記を読んでいるような自然な流れ
→ リプライを誘発する「問い」で締める
```

### 例文テンプレート

```
エフェクターの接続順って、調べても調べてもよく分からないまま何年も経ってたんですよね。

結論から言うと「歪み前・歪み・歪み後」の3つに分けて考えるだけで大体解決します。

歪みの前にあるものは「そもそもギターがこういう音だったら」って置き換えのイメージ。
歪みの後は「できた音をどう仕上げるか」って感じ。

ただ、これはあくまで基本なので好きな音がするなら何でもアリです。縛られなくていい。

みなさんはどんな基準で繋ぎ方決めてますか？
```

### Threads特有の注意点

- Xより「独り言っぽさ」「日記っぽさ」を出す
- 改行で「間」を作り、読んでいて息継ぎができる感覚に
- 「完全にこうすべき」より「こういう考え方もある」という柔らかい断言
- リプライ文化が強いので、最後の問いかけは必須

## PART 3｜コンテンツ設計の型集（弾いてみた層向けバリエーション追加）

### 型①「あるある解決型」（最頻出）

```
[悩みの共感] → [シンプルな結論] → [理由] → [でも自由でいい] → [コメント誘導]
```

### 型②「意外な事実型」

```
[え、そうなの？という事実] → [理由説明] → [実は自由] → [問いかけ]
```

例：「コーラスは歪みの後に繋ぐのが基本って言われてるけど、歪みの前に繋いだ時のエグみが好きな人もいます。正解はないんですよね。」

### 型③「比較検証型」

```
[AとBどっちが正解？] → [両方試してみた] → [違いの説明] → [好みで選べばいい]
```

### 型④「初心者救済型」

```
[初心者がよく迷うポイント] → [実はシンプル] → [一言でまとめると] → [安心させる締め]
```

### 型⑤「弾いてみた体験型」（新）

弾いてみた層へのリーチ専用フォーマット。

```
[演奏してて感じた違和感・あるある] → [その原因（技術解説）] → [対処法] → [でも気にしすぎなくていい]
```

例：
```
弾いてみた動画を録ると、なんか音がこもって聞こえる問題ありませんか。

原因の大半はピックアップの高さか、トーンノブが絞れてること。

ピックアップを少し上げるか、トーンを10時くらいまで開けるだけで結構変わります。

ただ、こもった音がその曲に合ってることもあるんで、気になる時だけ試してみてください。
```

## PART 4｜「弾いてみた層」へのリーチ戦略（Threads・X特化）

### 問題の構造

Threads上には「弾いてみた」動画投稿者が多いが、エンゲージは低い。
エンゲージが高いのは知識・こだわり系の発信者。
両層にリーチするには、**技術知識を「演奏体験の言語」で再翻訳する**ことが必要。

| 層 | 特徴 | エンゲージ | 理由 |
|---|---|---|---|
| 弾いてみた投稿者 | 多い | 低い | 「見せる」コンテンツ。議論が生まれにくい |
| 知識・こだわり系 | 少ない | 高い | 「比較・発見・意見」コンテンツ。返信・保存が生まれる |

### 言語ブリッジの原則

技術コンテンツの**内容は変えない**。フックと結びの言葉を「弾く体験」に翻訳するだけ。

| 技術的な表現 | 体験言語への翻訳 |
|---|---|
| ピックアップのインピーダンス | 弾いてみた動画の音がこもって聞こえる原因 |
| トーンコントロール回路 | トーンノブ、実は使い方次第で化ける話 |
| フレット素材の違い | チョーキングした時に音が詰まる感じの正体 |
| ネックの仕込み角 | セッティングが合ってるのになんか弾きにくい問題 |
| バッファとインピーダンス | 長いケーブルで音が死ぬやつの話 |

### Threadsでの実践

**① フックを「演奏体験」から始める**

```
❌ NG: ピックアップのインピーダンスについて解説します
✅ OK: 弾いてみた動画を撮ると、なんか音が死んでる気がする現象の話
```

```
❌ NG: トーンコントロールの回路を解説します
✅ OK: プロの弾いてみたって音がクリアなのに、自分だとなんか違う気がする理由
```

**② コメント巡回の弾いてみた層向けアプローチ**

弾いてみた投稿に「技術的な気づき」を押しつけでなく自然にコメントする。
→「この人、自分の音をわかってる」という印象を作る入口になる。

```
例：「音の輪郭がしっかりしてますね。
ピッキング位置とピックアップの距離感が合ってる感じがします」
```

NGパターン（説教・上から目線）：
```
「ピックアップの高さ調整したら音良くなりますよ」← 上から目線で嫌われる
```

**③ 技術説明の最後に「だから演奏でこうなる」を必ず入れる**

技術の話をしたあと、必ず弾く体験に結びつける一文を添える。

```
（技術説明の後に）
→ だから弾いてみた動画でギターの音だけこもって聞こえるのはこれが原因なことが多いです。
```

### Xリライト方針（弾いてみた層向け）

- タイトルに「弾いてみた」「録音」「動画の音」「なんか違う」等のワードを含めるパターンを持つ
- 冒頭は機材スペックでなく「演奏して感じた違和感・あるある」から入る
- 技術説明の後に「だから〇〇な音になる」という演奏との結びつけを1文入れる

## PART 5｜禁止事項・注意事項

| NG | 理由 |
|-----|------|
| 「〜しなければいけません」「〜が正解です」 | 押しつけ感が出てキャラから外れる |
| 専門用語の羅列（説明なし） | 「難しそう」で離脱される |
| 「続きは動画で」のみで価値を出し惜しむ | SNSで信頼が積み上がらない |
| 長すぎる前置き | 最初の2文で価値が伝わらないと離脱 |
| 「いいねお願いします」の連呼 | 押しつけがましい印象になる |

## PART 6｜まとめ｜バズる本質

**「知識 × 謙虚さ × 自由の許可」**

専門知識を持ちながら「でも縛られなくていい」と言い続けることで、教えているようで**視聴者の自己決定を尊重する**稀なポジションを取っている。これが幅広い層に刺さる最大の理由。

SNS投稿でもこの3要素を必ず入れること。

> **価値のある情報を先に出す → シンプルに説明する → でも自由でいいと解放する**
