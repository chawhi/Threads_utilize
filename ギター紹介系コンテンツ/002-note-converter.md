# Skills 002: note記事変換

## 基本情報

| 項目 | 内容 |
|---|---|
| **Skill名** | `note-converter` |
| **カテゴリ** | 記事執筆系 |
| **発動条件** | 「noteの記事に変換して」「note用に整形して」と言ったとき |

## 概要

X記事で書いた内容を、noteのフォーマットに最適化された形に変換するSkill。

### XとnoteのフォーマットFの違い

| 項目 | X記事 | note記事 |
|---|---|---|
| 文体 | 短文・フック重視 | 丁寧・読了率重視 |
| 改行 | 多め | 適度 |
| 目次 | なし | あり |
| 冒頭 | フック | 要約文 |

---

## SKILL.md 本体

```yaml
name: note-converter
description: >
  X記事の原稿をnoteフォーマットに変換する。
  「noteの記事に変換して」「note用に整形して」と言われたら発動。
```

---

## 変換処理の内容

1. **見出しの付け方** をnote向けに調整
2. **目次** を自動生成
3. **冒頭の要約文** を追加
4. 文体をX向けの短文スタイルからnote向けの丁寧な文体へ変換
5. 改行・段落構成をnoteの読了率に最適化
6. **画像プロンプトを適切な箇所に挿入**（下記ルール参照）

---

## 画像プロンプト挿入ルール

### 画像は2種類だけ

| 種類 | 役割 | CTA | レイアウト | サイズ |
|---|---|---|---|---|
| **アイキャッチ** | クリックさせる | **必須** | 左テキスト・右ビジュアルの分割型 | 1280×670px |
| **本文画像** | 理解を助ける | **なし** | 自由（比較図・断面図等） | 800×500px / 600×400px |

---

### 記法

```
<画像 横×縦px：[画像の内容説明]>
```

### アイキャッチの設計仕様

**レイアウト構造**

```
┌──────────────────┬──────────────────┐
│  単色背景        │                  │
│                  │  フラット        │
│  [小] 第X回      │  イラスト        │
│                  │        ↑        │
│  CTAテキスト     │   右下コーナーは │
│  （白・大・太）  │   余白を確保     │
│                  │        ↓        │
│  ─ オレンジ線 ─ │  [Geminiマーク   │
│                  │   セーフゾーン]  │
└──────────────────┴──────────────────┘
      左50%                右50%
```

**固定仕様（毎回変えない）**

| 要素 | 仕様 |
|---|---|
| サイズ | 1280×670px |
| 左半分幅 | 640px |
| 左背景色 | ダークチャコール `#2d2d2d` |
| 「第X回」位置 | 左端から48px・上端から52px、グレー `#888888`・24px |
| CTAテキスト位置 | 左端から48px・上端から180px起点 |
| CTAフォント | 白 `#FFFFFF`・太字・**80px固定**・最大幅520px・行間1.1 |
| オレンジライン | 左端から48px・下端から72px、幅220px・高さ4px・`#e8650a` |
| スタイル | ミニマルなフラットイラスト |
| 右下セーフゾーン | 右端20%・下端20%はイラスト要素を配置しない（GEMINIウォーターマーク用余白） |

> **重要：** CTAのフォントサイズは文字数に関わらず80px固定。文字数が多い場合は最大幅520px内で折り返す。位置指定をpxで固定することで記事ごとのばらつきをなくす。

**毎回変える部分**

- 「第X回」の回数
- CTAテキスト（15〜25字以内、改行は`/`で指定）
- 右側のイラスト内容（記事テーマに合わせる）

### CTAテキストの設計

**3原則**

| 原則 | NG | OK |
|---|---|---|
| 断言しない | 「絶対読むべき」 | 「これかもしれない」 |
| 読者を呼ぶ、押しつけない | 「ギタリスト必見！」 | 「音がこもる人へ」 |
| 体験言語で書く | 「ピックアップ解説」 | 「音がモコッとする原因」 |

**5パターン**

| パターン | 例 | 使いどき |
|---|---|---|
| A「〜な人へ」 | `チューニング狂いやすい人へ` | 悩みが明確な記事 |
| B「正体」 | `音がモコッとする原因` | 仕組み・理由を解説する記事 |
| C「知ると変わる」 | `知ると音作りが変わる話` | 概念・考え方の記事 |
| D「なんとなく」 | `なんとなく使ってたあのつまみ` | 初心者向け・入門記事 |
| E「シリーズ」 | `連載第5回｜ピックアップ編` | シリーズ継続読者向け |

### 本文画像の設計仕様

**目的：文章だけでは伝わらない概念を視覚化する**

- アイキャッチと**同じフラットイラストスタイル・チャコール＋オレンジ系の同系色**で統一
- CTAテキストは入れない
- 左右分割は不要。内容に合った構図で自由に設計
- 右下セーフゾーンの確保は不要（ウォーターマークが被っても支障ない）

**図解とイラストの分離ルール（重要）**

比較図・回路図・グラフなどの「情報を伝える図解」とキャラクター・装飾イラストを同一エリアに混在させない。

| ゾーン | 役割 | 入れてよい要素 | 入れてはいけない要素 |
|---|---|---|---|
| **図解ゾーン** | 情報を正確に伝える | グラフ・波形・回路図・比較表・ラベルテキスト | キャラクター・渦巻き・装飾的な流線 |
| **イラストゾーン** | 雰囲気・概念を伝える | キャラクター・概念的なビジュアル | 詳細な数値・比較データ・回路図 |

画像タイプ別のすみ分け：

- **比較図・回路図・グラフが主役の画像**：イラスト・キャラクターは入れない。白〜淡いグレーの背景にクリーンな図解のみで構成する
- **概念・雰囲気を伝えるイラストが主役の画像**：数値・データ・精密な図解は入れない。キャラクターや概念的なビジュアルで構成する
- **両方必要な場合**：上下または左右でゾーンを明確に分け、イラストが図解エリアに重ならないよう余白で区切る

**本文画像プロンプトのテキスト方針**

図解画像には理解に必要なラベル・補足テキストを入れてよい。ただしGeminiがpx座標などを誤描画しないよう以下を厳守する。

```
※ px数値・座標・%などの数値テキストは画像内に一切表示しないこと
```

入れてよいテキスト（プロンプトで明示指定したもののみ）：
- 列見出しラベル（例：「ボルトオン」「Cシェイプ」「メイプル」）※**日本語で記載すること**
- 音の傾向・特徴の1語補足（例：「明るい」「汎用性が高い」）※**日本語で記載すること**
- 図解の補助テキスト（例：矢印ラベル、接合方式の短い説明）※**日本語で記載すること**

入れてはいけないテキスト：
- px・座標・%などの数値
- プロンプトで指定していない説明文・タイトル
- キャプション・注釈の自動生成テキスト

**サイズ**

| 用途 | サイズ | 挿入タイミング |
|---|---|---|
| セクション図解 | 800×500px | 比較・構造・仕組みを説明するH2見出しの直後 |
| 補足イラスト | 600×400px | 文章だけでは伝わりにくい概念の段落末尾 |

---

### 本文画像を入れる条件

- **比較がある箇所**：A vs B を並べて説明しているとき（例：アルニコ vs セラミック）
- **構造・断面・回路の説明箇所**：パーツの内部や配置が関係する説明
- **「見た方が早い」概念の箇所**：文字だけでは空間イメージが伝わりにくいとき
- **視線リセットしたい箇所**：長い文章ブロックの後、新しいセクションへの切り替えとして

### 本文画像を入れない条件

- 1記事に（アイキャッチ含めて）5枚を超える場合は優先度の低いものを削る
- 同じ種類の画像が連続する場合は間隔を空ける
- 「まとめ」「コメント誘導」などの締めセクションには入れない
